# Формат протокола

## Транспорт

newline-delimited JSON-RPC 2.0 поверх stdio плагина:

- каждое сообщение — одна строка, UTF-8, завершение `\n`;
- пустые строки пропускаются;
- **stdout несёт только протокол** — логи идут в stderr;
- записывающая сторона сбрасывает буфер после каждого сообщения
  (интерактивные сессии).

## Сообщения

Запрос (ожидает ровно один ответ):

```json
{"id": 7, "method": "tools/call", "params": {"name": "open_qvm"}}
```

Уведомление (ответа не бывает никогда):

```json
{"method": "notifications/initialized"}
```

Ответ:

```json
{"id": 7, "result": {"content": []}}
{"id": 7, "error": {"code": -32000, "message": "no QVM loaded - call open_qvm first"}}
```

`id` — неотрицательное целое или строка (тип `Id` в SDK принимает оба;
`null`-id из спеки JSON-RPC не используется).

## Коды ошибок

| Код      | Значение                                                       |
|----------|----------------------------------------------------------------|
| `-32700` | ошибка разбора (кривая JSON-строка)                             |
| `-32601` | метод не найден                                                 |
| `-32602` | неверные параметры (нарушение схемы, нет полей)                 |
| `-32603` | внутренняя ошибка                                               |
| `-32000` | доменная ошибка плагина — «файл не найден», «нет сессии» и т.п. |

Дисциплина: запрос, дошедший до обработчика, не должен превращаться в
протокольную ошибку из-за сбоя *задачи* (плохой путь, пустой результат
фильтра). MCP-серверы дополнительно заворачивают сбои задач в результаты
инструментов с `isError: true` — см. доки resq-mcp.

## RESQ-хендшейк (опциональный, для не-MCP плагинов)

```text
-> {"id":1,"method":"initialize","params":{"protocolVersion":1,"client":"resq-gui"}}
<- {"id":1,"result":{"protocolVersion":1,"plugin":{"name":"x","version":"0.1.0"}}}
```

Плагин отвечает наибольшей поддерживаемой версией протокола, не
превосходящей запрошенную. `handshake::InitializeResult` строит ответ;
`service::Handshake::accepts` проверяет входящий запрос.

## MCP-хендшейк (MCP-серверы на этом SDK)

MCP-серверы не используют RESQ-хендшейк: Model Context Protocol определяет
свой `initialize` с согласованием возможностей, плюс
`notifications/initialized`, `ping`, `tools/list`, `tools/call`. SDK даёт
транспорт и конверты; поверхность MCP-методов — забота сервера (полный
пример — `resq-mcp/src/main.rs`).

## Замечания о фрейминге

- Специально нет заголовков `Content-Length` (стиль LSP): построчный
  фрейминг тривиально реализуется на любом языке и отлаживается `cat`-ом
  и пайпом.
- Кривая строка — ошибка разбора (или `TransportError::BadMessage` для
  in-memory использования); SDK-цикл просто возвращает ошибку хост-процессу.
